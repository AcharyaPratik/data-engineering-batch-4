SQL Joins

Once your data is split across tables, most real questions need more than one table at a time. A join combines rows from two tables based on a matching column. There are only four kinds — pick a tab below and watch what each one keeps.

Only rows that match on both sides. Maya (no vehicle type) and Electric (no driver) are both left out.

SELECT d.name, vt.type_name
FROM drivers d
INNER JOIN vehicle_types vt ON d.vehicle_type_id = vt.vehicle_type_id;

Every row from drivers (the left table). Maya still appears, with NULL where a matching vehicle type would go.

SELECT d.name, vt.type_name
FROM drivers d
LEFT JOIN vehicle_types vt ON d.vehicle_type_id = vt.vehicle_type_id;

Every row from vehicle_types (the right table). Electric still appears, with NULL where a matching driver would go.

SELECT d.name, vt.type_name
FROM drivers d
RIGHT JOIN vehicle_types vt ON d.vehicle_type_id = vt.vehicle_type_id;

Every row from both tables. Maya and Electric both appear, each with NULL on the side that has no match.

SELECT d.name, vt.type_name
FROM drivers d
FULL OUTER JOIN vehicle_types vt ON d.vehicle_type_id = vt.vehicle_type_id;

The four joins at a glance

JoinKeepsUse it when
INNER JOINRows matched on both sides onlyEvery row is guaranteed to have a match on the other side
LEFT JOINEvery row from the left tableYou want "everything, plus related data if it exists" — or to find rows with no match
RIGHT JOINEvery row from the right tableRare — same as a LEFT JOIN with the tables swapped
FULL OUTER JOINEvery row from both tablesYou need gaps on both sides visible at once

Common mistakes

MistakeWhat goes wrongFix
No ON condition (comma-separated tables)Every row pairs with every row — a cartesian productAlways write an explicit JOIN ... ON
Joining the same table twice, same alias"table name specified more than once" errorGive each join its own alias, e.g. pu / dr
Filtering the outer side in WHERESilently turns a LEFT JOIN back into an INNER JOINPut the condition in ON instead
Joining two "many" tables to one parentRow counts multiply, inflating SUM/COUNTAggregate each branch separately, then combine
Joining on a text column, not the keyCasing/whitespace differences silently drop matchesJoin on the id column; clean text once at insert time
