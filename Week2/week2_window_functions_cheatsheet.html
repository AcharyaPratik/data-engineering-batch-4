SQL Window Functions

GROUP BY collapses many rows into one per group. A window function computes the same kind of calculation — a rank, a running total, a comparison to a neighboring row — without collapsing anything: every original row stays, with a new column attached. Every example below runs against a small trips table.

Anatomy of a window function

SUM(fare_amount) OVER (
    PARTITION BY driver_id   -- optional: restart the calculation per group
    ORDER BY requested_at    -- required for ranking, LAG/LEAD, running totals
)

Drop the PARTITION BY and the function runs over the whole result set. Drop the ORDER BY on a ranking or offset function and the order — and the answer — is undefined.

Try it: same trips table, four functions

Numbers each driver's trips in the order they happened — restarting at 1 for every driver.

Partitioned by driver_id, ordered by requested_at

SELECT d.name driver_name, t.requested_at, t.fare_amount,
    ROW_NUMBER() OVER (
        PARTITION BY t.driver_id
        ORDER BY t.requested_at
    ) AS trip_number
FROM trips t
JOIN drivers d ON t.driver_id = d.driver_id;

Ranks every trip by fare, highest first — no partition, so all drivers compete together.

RANK() skips a number after a tie; DENSE_RANK() doesn't

SELECT d.name driver_name, t.fare_amount,
    RANK()       OVER (ORDER BY t.fare_amount DESC) AS fare_rank,
    DENSE_RANK() OVER (ORDER BY t.fare_amount DESC) AS fare_dense_rank
FROM trips t
JOIN drivers d ON t.driver_id = d.driver_id;

Adds up each driver's earnings trip by trip — the total so far, not the grand total.

Partitioned by driver_id, ordered by requested_at

SELECT d.name driver_name, t.requested_at, t.fare_amount,
    SUM(t.fare_amount) OVER (
        PARTITION BY t.driver_id ORDER BY t.requested_at
    ) AS running_total
FROM trips t
JOIN drivers d ON t.driver_id = d.driver_id;

Pulls each driver's previous trip fare onto the current row, so you can compare trip to trip.

Partitioned by driver_id, ordered by requested_at

SELECT d.name driver_name, t.requested_at, t.fare_amount,
    LAG(t.fare_amount) OVER (
        PARTITION BY t.driver_id ORDER BY t.requested_at
    ) AS prev_fare,
    t.fare_amount - LAG(t.fare_amount) OVER (
        PARTITION BY t.driver_id ORDER BY t.requested_at
    ) AS fare_change
FROM trips t
JOIN drivers d ON t.driver_id = d.driver_id;

Common mistakes

MistakeWhat goes wrongFix
Using a window function in WHEREWHERE runs before window functions are computed — the column doesn't exist yetWrap the query in a subquery or CTE and filter the outer query
No ORDER BY inside OVER() on a ranking functionEvery row can tie for rank 1 — the order is undefinedAlways give RANK / ROW_NUMBER / LAG an ORDER BY
Forgetting PARTITION BYA "per driver" running total silently becomes one running total for the whole tableAdd PARTITION BY for whatever "per group" means here
Treating RANK() and DENSE_RANK() as interchangeableRANK() leaves gaps after ties; DENSE_RANK() doesn't — different totalsPick the one that matches the report you're building
Expecting a window function to collapse rows like GROUP BYIt doesn't — every input row survives, with an extra columnUse a window function precisely when you need the detail rows and the aggregate together
🎯
You're ready when you can look at any OVER (...) clause and say what resets the calculation (PARTITION BY), what orders it (ORDER BY), and whether the row count changes (it never does).
